# v1.1beta 激光与电视导引

适用 Minecraft 1.21.1、NeoForge 21.1.240+、SBW 0.8.9.1 / 0.8.9.2。客户端、服务器同时更新到 v1.1beta（NeoForge 内部版本 1.1beta）；通信协议为 4。

## 玩家操作

### 激光照射

手持 SBW 原有火炮指示器，按住右键并对准目标表面或实体。有效照射时显示激光状态和红色光束/光点；松开、切换物品、死亡、离线或更换维度即停止照射。原有火炮绑定与开火功能继续保留。

激光弹发射前要求存在同编码、在射界和距离内且视线可达的照射点。可使用本人或 scoreboard 同队玩家的照射，优先本人；未获取有效照射不会消耗弹药。不同编码、敌方或另一维度的照射不会被接收。

默认编码为 1688，支持 1–9999。其他编码通过指示器的物品自定义数据设置，例如：

```mcfunction
/give @s superbwarfare:artillery_indicator[minecraft:custom_data={SBWLoadoutLaserCode:1688}] 1
```

对应弹种 JSON 的 `LaserCode` 必须一致。服务器配置 `laserRange` 为指示器照射范围，默认 2048 格，可设 16–4096；弹药自己的 `SeekRange` 另外限制接收距离。射线只经过已加载区块。

### 机载照射

已声明通用挂载的飞机/直升机支持同一机腹吊舱。F6 进入、K 锁定实体或 G 稳定地面，L 开启/停止照射；自由搜索时 L 会先固定当前有效落点。返回驾驶视角后照射继续；重新进入按 L 关闭，K/G 解锁或 R 回正也会关闭。遮挡/云台限位暂停供光，重新看见原目标后恢复；离席、死亡、断线、换维度或禁用吊舱立即失效。照射点不存档。

服务器 `aircraftLaserCode` 默认 1688，范围 1–9999；与弹药 `LaserCode` 一致。机载照射距离同时受 `laserRange` / `podRange` 限制。机载光源身份绑定飞机 UUID，不能由同一玩家改用手持指示器替代已发射弹药的原飞机光源。

### 断照、惯性与重新接收

激光导弹/航弹持续更新照射位置。信号中断或被遮挡后，按最后一次有效坐标继续惯性导引；恢复接收原照射者、相同编码的有效信号后，继续向新照射点转向。失去照射时无法知道移动目标的新位置。

导弹转向默认每游戏刻最多 5 度、航弹 4 度，硬上限 6 度/刻，保持当前速度大小再交给原生推进和重力更新；目标落到弹体后方时保持前飞，避免瞬间掉头。惯性阶段可实际撞击最后坐标附近的目标；仍受转弯半径、原生寿命、重力、碰撞和拦截影响，不保证每次命中。

### 电视锁定

新增 [独立吊舱视角](吊舱视角与激光外观.md)：F6 进入，鼠标中键拖动或方向键转动镜头，滚轮变倍，K 锁定，Enter 投放。退出视角后也可使用原生开火键；下方原有 K 键直接锁定路径继续保留。

挂载队列第一枚为 `TV` 弹药时，瞄准目标并按 **K** 锁定，再按 SBW 原有载具开火键。再次按 K 取消锁定，按键可在游戏设置中修改。锁定优先采用 SBW 已选中的实体/位置，否则使用服务端准星射线；服务端检查真实表面、距离、射界和遮挡。

可锁实体，也可锁固定地面位置。发射后目标身份和最后坐标写入弹体，射手转头、离开驾驶席、死亡或离线都不影响已发射弹药。弹体自身能看到原目标时更新位置；原目标被遮挡、离开视场或消失时继续飞向最后坐标，不自动换锁另一实体。固定点始终保持原坐标。

## 近防炮拦截

两种导引头仅接入 SBW `DestroyableProjectile`，且弹体实体类型必须属于 `superbwarfare:destroyable_projectile` 标签。AGM-65 和 MK-82 已满足原生条件。保留原生耐久、受伤与销毁逻辑，近防炮使用自身敌我、距离、来袭轨迹和武器规则选敌；导引头不会使弹体无敌或在击毁后复活。

测试已覆盖 Laser / TV × AGM-65 / MK-82 四种组合的原生近防炮目标筛选和实际近防炮弹碰撞伤害、销毁。近防炮是否及时命中仍由原生炮塔性能和交战情况决定。

## 数据和 Java 接入

本版新增 Kh-29L 激光弹、KAB-1500Kr / Kh-59MK 电视弹和各自完整模型；Kh-58UShK 仅保留转换资源。原四件资源保持原样，不针对单独载具适配。`docs/examples/` 的四份完整弹种示例用于后续接入，未打入生产数据包；未填写的模型字段会使用现有占位资源，制作正式弹药时再指定模型。

复制示例到数据包 `data/<命名空间>/ammo/<弹药id>.json`，并在载具完整数据文件 `Loadout.Allowed` 中加入弹药 id。原有 JSON 字段和注册流程见 README；导引参数如下：

| 字段 | 含义 | 默认值 |
|---|---|---|
| `Guidance` | `Laser`（也接受 SALH）或 `TV`（也接受 Television） | TV |
| `LaserCode` | 激光接收编码，整数 1–9999 | 1688 |
| `SeekRange` | 导引头接收/锁定距离，格；Laser/TV 应设置正值 | 512 |
| `SeekAngle` | 前向接收半锥角，度 | 20 |
| `TurnRate` | 转向角速度，度/游戏刻；允许 (0,45]，实际硬限 6 | 导弹 5 / 航弹 4 |
| `RenderProjectileModel` | 在原生弹体上显示本弹种完整模型，身份同步及存档；默认 false | false |
| `Projectile` | 实际 SBW 弹体；必须支持摧毁并具备上述标签 | superbwarfare:agm_65 |

通用数据弹物品示例：

```mcfunction
/give @s sbw_loadout:ammo[minecraft:custom_data={Ammo:"mymod:laser_missile"}] 1
```

Java 注册：

```java
LoadoutApi.register(AmmoType.builder("mymod:laser_missile")
    .displayName("激光制导导弹")
    .projectile("superbwarfare:agm_65")
    .guidance("Laser").laserCode(1688).turnRate(5)
    .damage(600).velocity(3).slots(1)
    .build());
```

第三方服务端发射器可在设置位置、初速度和 owner 后，生成入世界前调用：

```java
GuidanceApi.laser(projectile, designatorUUID, 1688, initialPoint, 1024, 30, 4);
GuidanceApi.television(projectile, targetUUIDOrNull, initialPoint, 1024, 30, 4);
```

这两个入口适用于可信服务端代码；调用者负责初始目标授权。自定义挂载自身的玩家发射路径会完成目标校验。激光指定者为正在使用火炮指示器的在线玩家 UUID，或正在照射的机载光源对应飞机 UUID；TV 传 null 实体身份表示固定坐标。只有有效服务器弹体可挂导引头，错误参数会抛出异常。

导引状态保存在实体持久数据 `SBWLoadoutSeeker` 中，包含目标身份、照射者、编码、最后坐标和转向参数；重载后可继续惯性/自主导引。激光实时照射源本身不存档，重新有效照射后才能恢复信号。发射前 TV 锁定在退出/死亡换身/跨维度时清除。
