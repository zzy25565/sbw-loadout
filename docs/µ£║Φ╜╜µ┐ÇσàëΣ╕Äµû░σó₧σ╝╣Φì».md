# v1.1beta：机载激光与新增弹药

适用 Minecraft 1.21.1、NeoForge 21.1.240+、SBW 0.8.9.1 / 0.8.9.2。客户端、服务器一起更新；网络协议为 4。NeoForge 不接受以 `v` 开头的内部版本，因此内部填写 `1.1beta`，发布文件名使用 `v1.1beta`。

## 本版弹药

| 弹药 ID / 物品 ID 后缀 | 用途 | 原生物理弹体 | 占用槽位 | 完整三角面 |
|---|---|---|---:|---:|
| `kh29l` / `ammo_kh29l` | 激光制导 | AGM-65 | 1 | 14,337 |
| `kab1500kr` / `ammo_kab1500kr` | 电视制导 | MK-82 航弹 | 3 | 33,967 |
| `kh59mk` / `ammo_kh59mk` | 按用户要求接电视制导 | AGM-65 | 2 | 23,740 |
| `kh58ushk` | 隐藏预留，仅模型与材质资源 | 未注册 | — | 24,766 |

物品命名空间均为 `sbw_loadout`。例如 `/give @s sbw_loadout:ammo_kh29l 8`。通用挂载的 `Loadout.Allowed` 必须加入对应弹药 ID，`Slots` 必须容纳弹药；仍不内置任何单机型适配。原有四件弹药保持可用，共七种内置可用弹药。

Kh-58UShK 没有物品、创造栏、挂载列表或 `data/*/ammo` 条目，`/give` 也没有该注册物品。预留资源位于 `assets/sbw_loadout/models/bedrock/ammo/kh58ushk.geo.json` 和 `textures/bedrock/ammo/kh58ushk/`；索引是 `models/bedrock/ammo/reserved.json`。未实现其专用导引。

初速、伤害、转向和槽位是游戏初始平衡值，可修改对应弹药 JSON，不代表真实武器参数。所有新增可用弹药启用 `RenderProjectileModel`；物品、飞行中的弹体使用各自完整网格；导弹的 SBW 超视距精简同步包也携带该模型身份。仍使用原生碰撞尺寸、推进/重力、寿命、爆炸、耐久和近防炮标签，没有因换模型改变原生受击机制。

## 机载自照射

1. 坐入已声明通用挂载的飞机/直升机驾驶席，挂载 Kh-29L。
2. 按 F6 进入独立吊舱，用中键拖动/方向键瞄准，滚轮变倍。
3. K 锁定实体，或 G 稳定地面点。
4. 按 L 开启激光，检查 `LASER ON / 1688`；自由搜索时按 L 也会先稳定准星下的实际可见点。
5. 目标处于弹药发射射界内时按 Enter 投放，也可返回驾驶视角后按原有载具开火键。传感器可以观察侧方，观察到目标不等于满足发射射界。
6. 返回驾驶视角后继续照射；要停止，F6 重新进入再按 L。取消锁定或 R 回正也关闭照射。

激光源位于与吊舱一致的机腹通用位置（载具中心下方 0.35 格），不逐机型添加可见的实体吊舱外壳或位置适配。相机、光束和服务端射线使用一致位置。驾驶飞机时世界、飞机与弹药持续运行，不提供自动驾驶或保高。

遮挡、超出云台范围、观测距离或加载区块范围时，照射信号暂停。原目标重回有效视线后恢复；不把挡路山体自动替换为原跟踪目标。离席、驾驶员死亡、断线、换维度、关闭服务器吊舱功能会立即停止。打开观测界面时心跳超时也关闭；正常返回驾驶视角后的持续照射不依赖界面心跳。

机载信号绑定原飞机 UUID；手持指示器信号绑定玩家 UUID。已经绑定原飞机的弹药不会在断照后任意改接其他光源。恢复同一飞机、相同编码的有效信号可重获；照射本身不存档，弹体保存最后点和引导状态。

服务器配置 `serverconfig/sbw_loadout-server.toml` 中 `aircraftLaserCode` 默认 1688（1–9999）。`laserRange`、`podRange` 默认各 2048 格，机载有效距离取两者共同限制；弹药接收范围和发射射界另行生效。射线不生成新区块。新 Kh-29L 默认 `LaserCode: 1688`。

## 协同、惯性、电视与拦截

同 scoreboard 队伍的玩家可使用机载或手持照射引导激光弹；陌生/敌方、异维度、不同编码信号不能作为发射解。没有有效照射点时不扣弹药。持续引导只更新最后有效位置，断照后继续朝最后点惯性飞行，不能继续获知移动目标位置。恢复信号时平滑转向，导弹默认 5 度/刻、航弹 4 度/刻、硬限 6 度/刻，不会瞬间掉头。

KAB-1500Kr 和 Kh-59MK 通过同一吊舱 K 锁定再 Enter 发射；发射后无需持续照射或占用吊舱。实体目标可自主跟踪；被遮挡或丢失时保留最后位置，不擅自换锁。固定地面点保持原坐标。

导弹、航弹保留原生可摧毁弹体机制，可被近防炮拦截。命中仍受转弯半径、目标运动、地形、弹药寿命和炮塔交战能力影响。

## 模型保真与复现

原始包四个 `.blend` 均没有图片贴图，仅有线性灰色基础材质（0.8 / 0.8 / 0.8，粗糙度 1，金属度 0）。没有补造涂装；材质用 sRGB 灰色 PNG 色块表示，不存在源图片降采样。四个原文件保存在 `source_models/`，逐字节与上传包核对。

转换只作居中及右手坐标旋转 `game=(sourceY,sourceZ,sourceX)`，源文件一米对应一格。保留所有源三角面、逐角法线、UV 和材料分组；不减面、不合并细节。校验文件 `model_review/new_ammo_conversion.json` 和 `validation/new_ammo_asset_checks.json` 记录源文件哈希、所有三角角点哈希与数量。HUD 16×16 图标单独生成，不改变三维模型。

```sh
# Blender 后台转换，不执行 .blend 内脚本
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --disable-autoexec --python tools/convert_blend_ammo.py -- "$PWD"
# 每件独立进程渲染，避免 Blender 重建多个场景时的清理问题
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --disable-autoexec --python tools/render_blend_ammo.py -- "$PWD" kh29l
# 其余三件使用 kab1500kr、kh59mk、kh58ushk；完成所有预览后生成物品数据和 HUD 图标
python3 tools/prepare_blend_ammo.py
python3 tools/validate_assets.py
python3 tools/validate_blend_ammo.py
```

资源校验脚本需要工程上两级仍有原上传 ZIP。四件预览见 `model_review/new_four_models.png`。实际游戏测试记录见 `validation/验收记录.md`；历史版本的通过记录不替代本版验收。
